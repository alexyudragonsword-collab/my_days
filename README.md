# 个人工作台（my_days）

[English README](README.en.md)

只供个人使用的本地工作生活管理 App。把每天的计划、自媒体创作、开发工作、咨询工作、健身、饮食和游戏娱乐集中在一个本地应用中，所有数据保存在你电脑上的一个 SQLite 文件里，不需要联网、注册或登录。

## 功能一览

- **首页总览**：今日概况、时间线（可拖拽调整时间）、待安排事项、快速备忘、需要关注、六个模块摘要
- **今日计划**：今日 / 本周 / 历史三视图，事项的时间、时长、优先级、完成 / 取消 / 延期，当日复盘
- **自媒体**：灵感 → 待策划 → 制作中 → 待发布 → 已发布 五阶段看板，发布链接与播放/点赞/评论数据
- **开发工作**：项目、里程碑、工作项（功能 / 需求 / Bug / 技术问题）、开发日志
- **咨询工作**：客户、咨询项目、沟通记录（含时长与费用）、交付物、跟进提醒
- **健身计划**：训练模板、逐组记录次数重量、上次同动作数据、身体数据与趋势
- **饮食计划**：每日营养目标、计划餐食与实际摄入、常用食物、当日热量蛋白质汇总
- **游戏娱乐**：清单状态、游玩计时、进度与下一次目标、累计时长（没有逾期压力）
- **数据与设置**：数据文件信息、手动 / 每日自动备份、安全恢复、ZIP 导出（JSON + CSV）、回收站、主题等偏好
- **中英双语**：界面语言可在「数据与设置 → 使用偏好」中切换中文 / English；业务数据中的状态、阶段等仍以中文规范值存储，仅在显示层翻译，切换语言不复制、迁移或修改任何业务数据
- **界面外观**：除默认外观外，另有「流光玻璃」（环境色、透明材质）、「Notion 笔记」（紧凑画布、纯平表面）、「Neo-Brutalism」（多色印刷、硬边框）三种独立外观，每种都支持浅色与深色主题；切换外观只改变界面样式，不影响任何业务数据

各业务模块的记录都可以“加入今日计划”，计划事项只保存关联而不复制业务数据；修改来源记录的标题，首页和今日计划会同步显示。

## 环境要求

- Node.js 18 或更高版本（推荐 22）
- 一款现代桌面浏览器（以 Chrome / Edge 为验收基准）

## 启动方式

首次使用先安装依赖（只需一次）：

```bash
npm install
```

之后每次使用：

| 系统 | 方式 |
| --- | --- |
| macOS | 双击项目根目录的 `启动个人工作台.command` |
| Windows 10/11 | 双击 `启动个人工作台.bat` |
| 任意系统（终端） | `npm run app:start` |

启动器会自动完成首次构建、在后台启动服务并打开浏览器；重复启动不会产生第二个服务，而是直接打开已在运行的页面。用完后点击页面顶部的「保存并退出」可安全关闭后台服务；直接关浏览器则服务留在后台，下次启动直接复用。

也可以手动运行：`npm run build && npm start`，然后打开 **http://127.0.0.1:5675**。服务只监听本机回环地址，同一网络的其他设备无法访问，并且会拒绝来自其他网站页面的跨站请求。

- 更换端口：设置环境变量 `MY_DAYS_PORT`
- 更换数据目录：设置环境变量 `MY_DAYS_DATA_DIR`（默认目录见下一节）

开发模式（前端热更新）：`npm run dev`，然后访问 http://127.0.0.1:5173 。

## 数据保存在哪里

默认使用各系统的标准应用数据目录：

| 系统 | 默认数据目录 |
| --- | --- |
| macOS | `~/Library/Application Support/MyDays/` |
| Windows | `%LOCALAPPDATA%\MyDays\` |
| Linux | `~/.local/share/MyDays/` |

旧版本使用的 `~/.my_days/` 中已有数据时会继续使用该目录，不做迁移。目录结构：

```
MyDays/
├── data/
│   └── my_days.db        ← 主数据文件（SQLite，所有业务数据都在这里）
├── backups/
│   ├── auto-YYYYMMDD-HHMMSS.db     ← 每日自动备份
│   ├── manual-YYYYMMDD-HHMMSS.db   ← 手动备份
│   ├── safety-YYYYMMDD-HHMMSS.db   ← 恢复前自动创建的安全备份
│   └── manifest.json               ← 备份的备注与“长期保留”标记
└── logs/                 ← 启动器方式运行时的服务日志
```

数据库结构变更通过 `server/migrations/` 中按序号命名的 SQL 迁移管理，升级版本后首次启动会自动应用。

在应用的「数据与设置」页可以看到主数据文件的完整路径、大小和最近修改时间。

## 备份与恢复

- **手动备份**：「数据与设置」→「立即备份」，随时创建完整备份。
- **自动备份**：应用每天自动备份一次（启动时和运行中每小时检查）；普通自动备份最多保留 30 份，勾选“长期保留”的备份不会被自动清理。
- **恢复**：在备份列表点击「恢复」，确认后系统会先自动创建一份当前数据的安全备份，再用所选备份覆盖数据；无效或损坏的备份会被拒绝，当前数据不受影响。
- **导出**：「导出 ZIP」生成压缩包，内含清单、机读的全量 JSON 和每个模块一份 CSV（可用 Excel 等表格软件打开）；导出不修改主数据，也不能替代备份。
- **导入**：「数据与设置」→「选择导出 ZIP 导入」，从导出文件完整恢复全部业务数据（用于迁移到新电脑）；导入会完整替换当前数据，替换前自动创建安全备份。

## 日常小贴士

- 顶部的「手动保存」会立即提交快速备忘 / 当日复盘草稿，并把数据落盘校验一遍；平时的编辑都是自动保存的，顶部会显示“保存中 / 已保存 / 保存失败”。
- `Ctrl / Command + K` 打开全局搜索，可跨模块搜索并直接跳转到记录。
- 删除的记录会先进入「数据与设置」页的回收站，可以恢复；永久删除需要再次确认。

## 测试与持续集成

```bash
npm run verify    # 构建 + 服务端集成测试（针对真实构建产物启动服务）
npm run test:e2e  # Chromium 浏览器端到端验收（需要 npx playwright install chromium）
# 本地已有 Chromium 时可指定：CHROMIUM_PATH=/path/to/chrome npx playwright test
```

验收标准 AC-001~040 与自动化测试的对应关系见 `docs/ACCEPTANCE.md`。仓库的 GitHub Actions 会在 Linux、macOS 和 Windows 上运行构建与服务端测试，并在 Linux 上运行浏览器端到端验收。
